# K8s Cluster — AWS (Terraform + Ansible)

This project automates the deployment of high-availability Kubernetes clusters on AWS using Terraform for infrastructure provisioning and Ansible for cluster configuration. It is designed to manage multiple independent clusters — across teams, environments, and AWS accounts — from a single codebase.

## Project Structure

```text
.
├── terraform/
│   ├── bootstrap/              # One-time: creates S3 state bucket per environment tier
│   ├── modules/
│   │   ├── vpc/                # VPC, subnets, IGW, NAT gateway, route tables
│   │   ├── security_groups/    # SGs for control plane, workers, and ALB
│   │   ├── iam/                # EC2 instance role with SSM access
│   │   ├── compute/            # EC2 instances (config-driven via for_each)
│   │   └── load_balancer/      # Internal NLB (k8s API) + public ALB (app traffic)
│   ├── environments/           # Per-cluster variable files (one per team × environment)
│   │   ├── platform-dev.tfvars
│   │   ├── platform-staging.tfvars
│   │   └── platform-prod.tfvars
│   ├── backends/               # Per-cluster backend configs (S3 key + bucket)
│   │   ├── platform-dev.hcl
│   │   ├── platform-staging.hcl
│   │   └── platform-prod.hcl
│   ├── scripts/
│   │   └── generate_inventory.sh  # Generates ansible/inventory-<cluster>.ini from Terraform outputs
│   ├── main.tf                 # Root module — wires all modules (shared, never changes)
│   ├── variables.tf            # All input variables
│   ├── outputs.tf
│   ├── providers.tf            # AWS provider with optional assume_role
│   └── terraform.tf            # Terraform version + partial S3 backend
└── ansible/
    ├── roles/
    │   ├── common/             # containerd, kubelet, kubeadm, kubectl, sysctl
    │   ├── k8s_control_plane/  # kubeadm init + join for HA control plane
    │   └── k8s_worker/         # kubeadm join for worker nodes
    ├── group_vars/all.yml       # k8s version, CNI CIDR, repo URLs
    ├── site.yml                 # Master playbook
    └── inventory-<cluster>.ini  # Generated by terraform/scripts/generate_inventory.sh
```

## Design

### The Core Problem

A real organisation runs many clusters — one per team, one per environment. A `payments` team needs `payments-dev`, `payments-staging`, and `payments-prod`. A `platform` team needs the same. These clusters must be fully independent: separate state, separate lifecycles, no shared blast radius.

### What Changes Between Clusters, What Doesn't

Every cluster has the same shape: VPC + security groups + IAM + compute + load balancer. What differs between `payments-dev` and `platform-prod` is only the **values** — node sizes, counts, CIDRs, tags, AWS account.

This means the code stays constant, and **variable files drive everything**.

### Layout

```text
terraform/
├── modules/           # written once — shared by every cluster
├── environments/      # one .tfvars per cluster — pure config data, no logic
└── backends/          # one .hcl per cluster — 3 lines pointing to an S3 key
```

`main.tf`, `variables.tf`, and the modules never change as you add clusters. Only two small files are added per new cluster: a `.tfvars` and a `.hcl`.

### What scales with cluster count

| File type | Count | Contains |
| --- | --- | --- |
| `environments/<team>-<env>.tfvars` | 1 per cluster | Node sizes, counts, CIDRs, tags |
| `backends/<team>-<env>.hcl` | 1 per cluster | S3 bucket name + state key |
| `main.tf` | 1 total | Module wiring — never changes |
| `variables.tf` | 1 total | Variable declarations |
| `modules/` | 1 set | Reusable infrastructure components |

### State isolation

Each cluster's state is stored under its own key in an environment-tier S3 bucket:

```text
ntegra-k8s-dev-tfstate/
  platform/dev/terraform.tfstate
  payments/dev/terraform.tfstate

ntegra-k8s-prod-tfstate/
  platform/prod/terraform.tfstate
  payments/prod/terraform.tfstate
```

The `bootstrap/` module creates one S3 bucket per tier (`dev`, `staging`, `prod`) using Terraform workspaces.

### Multi-account support

The provider accepts an optional `assume_role_arn`. Set it per cluster in `.tfvars`:

```hcl
# environments/payments-prod.tfvars
assume_role_arn = "arn:aws:iam::111122223333:role/TerraformRole"

# environments/payments-dev.tfvars
assume_role_arn = null   # use default credentials
```

No code changes are needed when adding a new AWS account — only a new value in the relevant `.tfvars`.

### Adding a new cluster

1. Copy an existing `environments/<team>-<env>.tfvars` and update the values
2. Copy an existing `backends/<team>-<env>.hcl` and update the `key` field
3. Run bootstrap for the tier if the S3 bucket does not yet exist
4. `terraform init -backend-config=backends/<team>-<env>.hcl`
5. `terraform apply -var-file=environments/<team>-<env>.tfvars`

## Architecture

### Infrastructure Layer (Terraform)

- **Platform**: AWS EC2 (Amazon Linux 2023, dynamically resolved via AMI data source)
- **Networking**: Custom VPC with 3 public subnets (ALB) and 3 private subnets (nodes) across 3 AZs
- **Node access**: IAM instance profile with `AmazonSSMManagedInstanceCore` — no bastion, no public IPs on nodes
- **Config-driven**: All node counts, instance types, and networking come from `environments/<cluster>.tfvars`. Adding a worker = adding a map entry + `terraform apply`
- **State**: Remote state in S3 with native S3 locking (`use_lockfile = true`, requires Terraform ≥ 1.13)

### Load Balancers

| Load Balancer | Type | Scope | Purpose |
| --- | --- | --- | --- |
| `<cluster>-api-nlb` | Network (NLB) | Internal | k8s API server HA — port 6443 → control plane nodes |
| `<cluster>-app-alb` | Application (ALB) | Internet-facing | Application ingress — port 80 → worker nodes |

The NLB DNS name is injected into the Ansible inventory as `k8s_api_endpoint` and used as `--control-plane-endpoint` in `kubeadm init`.

### Kubernetes Layer (Ansible)

- **k8s version**: 1.30
- **Container runtime**: containerd
- **CNI**: Flannel (`10.244.0.0/16`)
- **HA control plane**: 3 nodes joined via `kubeadm init --upload-certs`

### Local authentication (SSO / JWT short-lived tokens)

This project uses AWS IAM Identity Center (SSO) for local runs. Both the Terraform provider and the S3 backend pick up credentials from the `AWS_PROFILE` environment variable, so set it once before running any Terraform commands:

```bash
export AWS_PROFILE=ntegra-sso-adm
aws sso login --profile ntegra-sso-adm
```

| Context | Auth mechanism |
|---|---|
| Local runs | `AWS_PROFILE` env var → SSO JWT tokens via `aws sso login` |
| `terraform init` (S3 backend) | `AWS_PROFILE` picked up automatically |
| `terraform plan/apply` (provider) | `AWS_PROFILE` picked up when `aws_profile = null` in tfvars, or explicit `aws_profile` value overrides it |
| CI/CD pipelines | IAM role attached to the runner — `AWS_PROFILE` not set |

> Do not hardcode the profile in `backends/*.hcl` — CI/CD runners authenticate via IAM role and do not have a named profile.

### Pre-commit hooks (one time per clone)

Pre-commit hooks enforce formatting, validation, linting, and documentation on every commit. Enable them after cloning:

```bash
pre-commit install
```

Hooks that run on every `git commit`:

| Hook | Tool | What it does |
|---|---|---|
| `terraform-fmt` | `terraform fmt` | Auto-formats all `.tf` files recursively |
| `terraform-init-check-*` | bash | Fails early if `terraform init` has not been run |
| `terraform-validate-*` | `terraform validate` | Validates root module and bootstrap module |
| `tflint` | `tflint` | Lints all modules using the AWS ruleset |
| `terraform-docs` | `terraform-docs` | Injects variable/output tables into `terraform/README.md` |

Before your first commit, run `terraform init` in the relevant module directories so the init-check hooks pass:

```bash
# Root module (after bootstrap buckets exist and backends/*.hcl are filled in)
terraform -chdir=terraform init -backend-config=backends/platform-dev.hcl

# Bootstrap module
terraform -chdir=terraform/bootstrap init
```

To run all hooks manually against the full codebase without committing:

```bash
pre-commit run --all-files
```

### Step 1 — Bootstrap state buckets (one time per environment tier)

```bash
cd terraform/bootstrap

terraform init
terraform workspace new dev
terraform apply -var="environment=dev" -var="aws_region=eu-west-2" -var="tag_who=ntegra"

terraform workspace new staging
terraform apply -var="environment=staging" -var="aws_region=eu-west-2" -var="tag_who=ntegra"

terraform workspace new prod
terraform apply -var="environment=prod" -var="aws_region=eu-west-2" -var="tag_who=ntegra"
```

Copy each `state_bucket_name` output into the corresponding `backends/<team>-<env>.hcl` files.

### Step 2 — SSH key management

SSH keys are **fully managed by Terraform** — no manual key generation or AWS Console steps required.

On `terraform apply`, the `keys` module:
1. Generates an ED25519 key pair using the `tls` provider
2. Uploads the public key to AWS as an EC2 Key Pair (named after the cluster)
3. Stores the private key in **AWS Systems Manager Parameter Store** as a `SecureString` at `/<cluster_name>/ssh-private-key`

The private key never touches the local filesystem during provisioning. `generate_inventory.sh` retrieves it from SSM at inventory generation time and saves it to `~/.ssh/<cluster_name>` (outside the repo, `chmod 600`).

**Keys are stable across scale operations.** Terraform is idempotent — the key resources are created once and recorded in state. Adding or removing nodes in `tfvars` and running `terraform apply` only affects the `aws_instance` resources; the key pair and SSM parameter show `no changes` every time.

**Cost:** SSM Parameter Store SecureString parameters are **free** for standard tier (under 4 KB). ED25519 private keys are ~400 bytes. This costs nothing, unlike Secrets Manager ($0.40/secret/month).

**What is never committed to git:**
- Private keys (`*.pem`, `*.key`, `id_ed25519*`, etc.)
- Generated Ansible inventories (`ansible/inventory-*.ini`)
- Kubeconfig files (`*.kubeconfig`)

> **Security note:** The `tls_private_key` resource stores the private key in the Terraform state file. The state is encrypted at rest in S3 (AES256). Access to the state bucket should be restricted via IAM to those who need it.

### Step 3 — Provision a cluster

```bash
cd terraform

terraform init -backend-config=backends/platform-dev.hcl
terraform plan  -var-file=environments/platform-dev.tfvars
terraform apply -var-file=environments/platform-dev.tfvars
```

To switch to a different cluster:

```bash
terraform init -reconfigure -backend-config=backends/platform-prod.hcl
terraform apply -var-file=environments/platform-prod.tfvars
```

### Step 4 — Generate Ansible inventory

```bash
terraform/scripts/generate_inventory.sh
# writes ansible/inventory-<cluster_name>.ini
```

### Step 5 — Configure Kubernetes

```bash
cd ansible
ansible-playbook -i inventory-ntegra-platform-dev.ini site.yml
```

## Cluster Configuration

All cluster parameters are driven by `terraform/environments/<team>-<env>.tfvars`:

```hcl
cluster_name = "ntegra-platform-prod"
environment  = "prod"
team         = "platform"
aws_region   = "eu-west-2"
aws_profile  = null
assume_role_arn = null   # set to cross-account role ARN for multi-account

availability_zones   = ["eu-west-2a", "eu-west-2b", "eu-west-2c"]
vpc_cidr             = "10.2.0.0/16"
public_subnet_cidrs  = ["10.2.0.0/24", "10.2.1.0/24", "10.2.2.0/24"]
private_subnet_cidrs = ["10.2.10.0/24", "10.2.11.0/24", "10.2.12.0/24"]

ssh_key_name     = "ntegra-k8s-key"
ssh_allowed_cidr = "10.0.0.0/8"

manager_nodes = {
  "1" = { instance_type = "t3.medium", disk_size_gb = 50, az_index = 0 }
  "2" = { instance_type = "t3.medium", disk_size_gb = 50, az_index = 1 }
  "3" = { instance_type = "t3.medium", disk_size_gb = 50, az_index = 2 }
}

worker_nodes = {
  "1" = { instance_type = "t3.xlarge", disk_size_gb = 200, az_index = 0 }
  "2" = { instance_type = "t3.xlarge", disk_size_gb = 200, az_index = 1 }
  "3" = { instance_type = "t3.xlarge", disk_size_gb = 200, az_index = 2 }
}

tag_who  = "platform-team"
tag_what = "k8s-cluster"
tag_why  = "platform-services-prod"
```

`az_index` is a zero-based index into `availability_zones`. Each node is placed in the corresponding private subnet. VPC CIDRs must be unique per cluster when deploying into the same AWS account.

## Scaling Workers

Add an entry to `worker_nodes` in the relevant `.tfvars` and re-apply:

```hcl
"4" = { instance_type = "t3.xlarge", disk_size_gb = 200, az_index = 0 }
```

```bash
terraform apply -var-file=environments/platform-prod.tfvars
terraform/scripts/generate_inventory.sh
cd ansible && ansible-playbook -i inventory-ntegra-platform-prod.ini site.yml
```

Only the new node is affected — existing nodes are not re-provisioned.

## Cluster Access

### Extract Kubeconfig

```bash
# Get the first CP instance ID from Terraform output
CP_ID=$(cd terraform && terraform output -json cp_instance_ids | jq -r '."1"')

# Start an SSM session
aws ssm start-session --target "$CP_ID" --region eu-west-2

# Inside the session:
sudo cat /etc/kubernetes/admin.conf
```

Save the output and update the `server:` field to point to the NLB DNS:

```bash
cd terraform && terraform output api_nlb_dns_name
```

### Option A: Isolated (recommended)

```bash
export KUBECONFIG=$(pwd)/ntegra-platform-prod.kubeconfig
kubectl get nodes -o wide
```

### Option B: Merged

```bash
cp ~/.kube/config ~/.kube/config.bak
KUBECONFIG=~/.kube/config:./ntegra-platform-prod.kubeconfig kubectl config view --flatten > ~/.kube/config_new
mv ~/.kube/config_new ~/.kube/config
kubectl config use-context kubernetes-admin@kubernetes
```

### Option C: direnv

```bash
echo "export KUBECONFIG=\$PWD/ntegra-platform-prod.kubeconfig" > .envrc
direnv allow
```

## Terraform State

The S3 backend is configured per cluster via `terraform/backends/<team>-<env>.hcl`. The bootstrap module creates:

- **S3 bucket** — versioned, AES256-encrypted, public access blocked
- One bucket per environment tier (`dev`, `staging`, `prod`) — shared across all teams in that tier

State keys follow the pattern `<team>/<env>/terraform.tfstate`, so all clusters for a tier share one bucket without colliding.

To inspect or manage state:

```bash
cd terraform
terraform state list
terraform force-unlock <lock-id>   # only if a lock is stale
```
